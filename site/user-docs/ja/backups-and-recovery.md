# バックアップと復旧

## バックアップを作成する

**設定** → **データとバックアップ** で **バックアップフォルダー** を選び、**バックアップを作成** を選択します。対応ブラウザーでは、Warplyn はそのフォルダーだけに書き込む許可を求めます。

[![バックアップフォルダー、バックアップを作成 と バックアップを復元 の操作、自動バックアップの設定が表示された Data and backups の設定画面。](/images/backups-and-recovery.png)](/images/backups-and-recovery.png)

*デスクトップアプリの データとバックアップ 設定。*

::: tip バックアップに含まれる内容
新しい `.skladno` バックアップには、データベース、現在のユーザーが作成した *スキル*、その *スキルの保存済みバージョン*履歴、ファイルマニフェストが含まれます。`.env` ファイルや API キーは含まれません。
:::

::: tip ブラウザーでのバックアップ制限
ブラウザーでのバックアップ転送では、1 ファイルあたり最大 100 MB、合計 500 MB まで対応しています。より大きなローカルデータにはデスクトップアプリを使ってください。
:::

デスクトップアプリでは、データベースの各スナップショットに隣接して `.sqlite.skills` フォルダーが作成されます。このフォルダーには、現在のユーザーが作成した *スキル*、その *スキルの保存済みバージョン*履歴、個人用スペル単語、マニフェストが含まれます。スナップショットをコピーまたは復元するときは、`.sqlite` ファイルと `.sqlite.skills` フォルダーを一緒に保管してください。ブラウザーのバックアップには個人用スペル単語は含まれません。

古い `.sqlite` バックアップにはデータベースだけが含まれます。これを復元しても、現在の *スキル*ファイルと履歴は保持されます。

## 自動バックアップ

**自動バックアップ** を **毎日** に設定すると、Warplyn の起動後まもなくスナップショットが作成され、その後は起動中 24 時間ごとに作成されます。ブラウザーでは、選択したフォルダーを使う許可が必要です。自動バックアップに失敗した場合は、フォルダーを確認して手動でバックアップしてください。次回の予定された試行は引き続き有効です。

**自動バックアップの保持数** では、Warplyn が保持する自動スナップショットの数を設定します。削除されるのは古い自動スナップショットだけで、手動で作成したバックアップは常に保持されます。

## バックアップを復元する

1. **設定** → **データとバックアップ** で **バックアップを復元** を選択します。
2. 復元するバックアップを選びます。Warplyn はファイルを確認し、現在のデータベースと *スキル*ファイルの復旧用コピーをローカルに保持します。
3. 復元が完了したら、*記事*と *保存済みバージョン*を確認します。

`.skladno` バックアップ、または関連フォルダー付きのデスクトップスナップショットを復元すると、データベースと保存済みの *スキル*が置き換わります。データベースのみの古い `.sqlite` バックアップを復元した場合は、データベースだけが置き換わります。

デスクトップバックアップを復元すると、保存済みの個人用スペル単語も辞書に追加されます。既存の単語は保持されます。個人用単語を含まない古いバックアップでは、辞書は変更されません。ダウンロード済み言語辞書とスペルチェックの事前読み込み設定は含まれません。

::: warning 復元後の AI 設定
復元しても、このインストールにすでにある AI 接続、認証情報、モデル選択は維持されます。接続が設定されていない場合、バックアップから環境変数の名前と参照先が復元されますが、API キーや環境変数の値は復元されません。このコンピューターで不足している変数を設定し、**設定** → **AIアシスタント** でモデルを選択してください。保存済み API キーを使う接続は、新しいインストールにはインポートされません。設定で追加してください。ほかの設定は復元されます。復元に失敗してロールバックした場合、以前の AI 設定が保持されます。
:::

## データベースのみのバックアップを手動で復旧する

この手順は旧形式の `.sqlite` バックアップに限って使用してください。データベースを元の場所に戻すまで Warplyn を停止したままにします。

1. 現在のローカルデータベースをコピーします。
2. 設定済みの Warplyn データフォルダー内にある `skladno.sqlite` を、バックアップで上書きします。
3. Warplyn を起動し、*記事*と *保存済みバージョン*を確認します。

*スキル*を含むバックアップを復元するには、**設定** の **バックアップを復元** を使います。Warplyn がマニフェストと *スキル*履歴も確認して復元できます。

## バックアップを作成できない場合

Warplyn はアクティブなデータベースと編集セッションを変更しません。保存先のフォルダーが存在し、アカウントに書き込み権限があることを確認してから再試行してください。

## ファイルのアクセス権

既定では、ローカルサービスはデータベースを `~/.warplyn` に保存します。別のフォルダーを使うには `WARPLYN_DATA_DIR` を設定します。Warplyn は `SKLADNO_DATA_DIR` を無視し、Skladno の旧データ保存場所と重なるフォルダーは使用しません。Skladno から移行する場合は、別の Warplyn フォルダーを選び、バックアップを復元してください。

POSIX システムでは、アップグレード後も含め、データフォルダーと SQLite ファイルへのアクセスを自分のアカウントに制限します。Windows では Windows が管理するファイルシステムのアクセス権が使われます。ブラウザーで作成したバックアップファイルは、選択したフォルダーのアクセス権を使います。バックアップは非公開のフォルダーに保存し、共有または同期フォルダーを使う前に共有設定を確認してください。
