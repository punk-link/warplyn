# Skladno から Warplyn への移行

Warplyn は独立したアプリケーションとして提供されています。復元したデータを確認できるまで、Skladno とそのデータを残してください。稼働中のデータフォルダーを Warplyn に移動しないでください。

[最新の Warplyn リリース](https://github.com/punk-link/warplyn/releases/latest)から Windows 11 x64 インストーラーまたは Debian x64 パッケージをダウンロードします。プラットフォームごとの手順は[インストール](installation.md)を参照してください。

移行の前に、**設定** → **データとバックアップ** で **バックアップフォルダー** を選び、**バックアップを作成** を選択してください。各 `.sqlite` バックアップと、その隣にある `.sqlite.skills` フォルダーを一緒に保管します。詳しくは[バックアップと復旧](backups-and-recovery.md)を参照してください。

## 移行手順

1. Skladno で進行中の AI 処理を完了またはキャンセルし、アプリを閉じてから再度開き、最新のチェックポイントが保存されていることを確認します。バックアップ作成中は、外部から著者の *スキル*ファイルを編集しないでください。
2. カスタムデータディレクトリーを使用している場合も含め、Skladno を開いた状態で、手動でバックアップを作成します。`.sqlite` ファイルと隣接する `.sqlite.skills` フォルダーは、元の名前のまま一緒に保管してください。バックアップ作成後、Skladno を閉じます。
3. Warplyn を別の空のプロファイルにインストールして開きます。稼働中の Skladno データディレクトリーを指定しないでください。
4. **設定** → **データとバックアップ** で移行用バックアップフォルダーを選び、**バックアップを復元** を選択します。Skladno のスナップショットを選び、置き換えを確認して Warplyn が再起動するまで待ちます。Warplyn にすでに作業データがある場合は、先に Warplyn 自体のバックアップを作成してください。復元するとデータが置き換わり、データベースは結合されません。
5. 新しい執筆を始める前に、*記事*、最新の *下書き*、*保存済みバージョン*の履歴、アシスタントとの会話、*設定*、公開プロフィール、著者の *スキル*を確認します。
6. **設定** → **AIアシスタント** で接続を再度追加し、用途ごとのモデルを選択します。認証情報はバックアップに含まれないため、復元すると保存済みの接続とモデル選択が消去されます。Skladno の認証情報は変更されません。
7. 環境変数を使う接続では、変数名を再度追加し、Warplyn がその変数を読み取れることを確認します。バックアップに `.env` ファイルやその値は含まれません。
8. 今後のバックアップ用に、Warplyn で別のフォルダーを選びます。更新時のネットワークとテレメトリーの設定も改めて選択してください。移行では、バックアップフォルダーの設定、テレメトリー ID、ダウンロード済みの更新、保留中の復旧記録はコピーされません。

`.sqlite.skills` フォルダーを伴うネイティブバックアップでは、現在の著者の *スキル*と不変の *スキル*履歴が復元されます。データベースのみの古い `.sqlite` スナップショットではデータベースが復元され、移行先の *スキル*は変更されません。バックアップに含まれていないファイルは復元できません。データベースのファイル名とマニフェスト形式は Skladno との互換性を保っています。

## 復旧

復元を確認できるまで Skladno をインストールしたままにしてください。アプリ間で後からの編集内容が同期または統合されることはありません。Skladno に戻ると、移行前の状態に戻ります。

復元に失敗した場合は、Skladno を引き続き使用し、元のバックアップ一式を保管してください。Warplyn はバックアップを確認し、復元前のデータをスナップショットに保存します。復元後に起動できなければ、そのスナップショットから元の状態に戻します。報告された問題を解決してから再試行してください。[バックアップと復旧](backups-and-recovery.md)および[更新の復旧](update-recovery.md)も参照してください。

Warplyn は既定で `~/.warplyn` を使用し、カスタムフォルダーには `WARPLYN_DATA_DIR` を使います。稼働データの保存先として `SKLADNO_DATA_DIR` は無視され、既知の旧データ保存場所と重なるパスは拒否されます。稼働中の SQLite データベースをコピーせず、空の別フォルダーを使って復元してください。
