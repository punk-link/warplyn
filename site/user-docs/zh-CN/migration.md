# 从 Skladno 迁移到 Warplyn

Warplyn 是独立应用。请保留 Skladno 及其数据，直到确认恢复的内容无误。不要将 Skladno 正在使用的数据目录移入 Warplyn。

从[最新 Warplyn 发布版本](https://github.com/punk-link/warplyn/releases/latest)下载 Windows 11 x64 安装程序或 Debian x64 软件包。平台安装说明请参阅[安装](installation.md)。

迁移前，请前往 **设置** → **数据与备份** 选择 **备份文件夹**，然后选择 **创建备份**。每个 `.sqlite` 备份都应与其旁边的 `.sqlite.skills` 文件夹放在一起。详情请参阅[备份与恢复](backups-and-recovery.md)。

## 迁移步骤

1. 在 Skladno 中完成或取消正在运行的 AI 任务，然后关闭并重新打开应用，以保存最新的*草稿*检查点。创建备份期间，请勿从外部编辑作者的*技能*文件。
2. 在正在运行的 Skladno 应用中创建手动备份，即使它使用自定义数据目录也一样。请保留 `.sqlite` 文件和旁边的 `.sqlite.skills` 文件夹及其原始名称，并将二者放在一起。备份完成后关闭 Skladno。
3. 在独立的空配置中安装并打开 Warplyn。不要将其指向 Skladno 正在使用的数据目录。
4. 前往 **设置** → **数据与备份**，选择迁移备份目录，然后选择 **恢复备份**。选择 Skladno 快照，确认替换并等待 Warplyn 重启。如果 Warplyn 中已有内容，请先创建自己的备份：恢复会替换现有内容，不会合并数据库。
5. 开始新写作前，请检查*文章*、最新的*草稿*、*已保存版本*历史、助理对话、**设置**、发布配置和作者*技能*。
6. 前往 **设置** → **AI助理** 重新添加连接，并为各用途选择模型。恢复会清除已保存的连接和模型选择，因为凭据不包含在备份中。Skladno 中的凭据保持不变。
7. 对于环境变量连接，请重新添加变量名称，并确认该变量存在于 Warplyn 进程环境中。备份不会复制 `.env` 文件或其中的值。
8. 为 Warplyn 选择单独的长期备份目录，并重新设置更新网络和遥测偏好。迁移不会复制备份目录偏好、遥测身份、已暂存的更新或待处理的恢复记录。

包含 `.sqlite.skills` 文件夹的原生备份会恢复当前作者*技能*及其不可变的*技能*历史。较旧的纯数据库 `.sqlite` 快照只恢复数据库，并保持目标位置的*技能*不变；它们无法恢复原本不包含的文件。数据库文件名和清单格式仍与 Skladno 兼容。

## 恢复

在确认恢复成功前，请保留 Skladno。两个应用不会同步或合并之后的编辑。返回 Skladno 时，它会保持迁移前的状态。

如果恢复失败，请继续使用 Skladno 并保留原始备份文件对。Warplyn 会验证备份并保留目标位置的恢复快照；启动失败时会回滚到该快照。解决报告的问题后重试。请参阅[备份与恢复](backups-and-recovery.md)和[更新恢复](update-recovery.md)。

Warplyn 默认使用 `~/.warplyn`，自定义目录请设置 `WARPLYN_DATA_DIR`。对于活动数据，Warplyn 会忽略 `SKLADNO_DATA_DIR`，并拒绝与已知旧目录重叠的路径。请使用独立的空目录并恢复备份，不要复制正在使用的 SQLite 数据库。
